Where does ret go?

Explore the difference between a thread's first start and a later resume by tracking the ready queue and saved rsp. This exercise runs in your browser.

Learning goal

For each switch, predict which logical thread runs next and where ret in st_ctx_swap goes. Explain your reasoning using the queue operation and the value referenced by ctx.rsp.

This is a symbolic model of st.c and ctx.S. It does not execute the code or show actual register values or addresses. Use the gdb exercise in the README to inspect the real program.

Before you start (about 3 minutes)

Plan for 15–20 minutes in total. Read the Prerequisites in the README and sections 1–3 of "Context switch" first.

ctx.rsp is the address of a location on the stack. The value stored at that location is the return destination. memory[ctx.rsp] below represents the 8 bytes at that location.

save:    prev.ctx.rsp = rsp
restore: rsp = next.ctx.rsp
ret:     rip = memory[rsp]; rsp = rsp + 8

This excerpt shows only rsp and ret. The implementation also saves and restores other registers and FP control state. The call chain shown in the README assumes its standard build without optimization.
